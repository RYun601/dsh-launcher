# dsh-launcher 自更新命令设计

> 日期：2026-09-05。代码基线：`9d1433a2e43b14fb87701527ed6b2bff27e77117`，`VERSION = 0.1.11`。
> 本文是待实施方案。当前仓库没有本文提出的自更新命令，本次仅交付文档。
> 相关审查：[代码审查与功能路线图](repository-review-and-roadmap-2026-09-05.md)。

## 1. 目标与命令命名

让已安装启动器的用户通过 `deepseek` 更新 dsh-launcher 自身，保留已有 DSH 运行时、用户配置和安装位置。继续区分 GitHub 上的启动器发行版与 npm 上的 DSH 发行版。

建议保持现有命名规则，增加以下两个互斥动作：

| 命令 | 状态 | 行为 |
| --- | --- | --- |
| `deepseek --update` | 已有 | 查询 DSH 本体更新 |
| `deepseek --upgrade` | 已有 | 升级 DSH 本体 |
| `deepseek --update-launcher` | 拟新增 | 只查询启动器的本地版本和 GitHub 稳定发行版，输出更新提示 |
| `deepseek --upgrade-launcher` | 拟新增 | 下载、验证并更新当前安装位置的启动器 |

`--self-update` 也容易理解，但会使现有 `update = 检查`、`upgrade = 执行` 的规则不一致。第一版采用上表两个完整名称，不同时增加别名，减少参数组合和文档成本。

第一版不开放预发布通道、强制降级、任意下载 URL 或后台自动更新。用户主动执行 `--upgrade-launcher` 即表示请求更新；服务忙、路径不安全或验证失败时应直接报错，不能静默退回普通启动。

## 2. 方案选择

| 方案 | 优点 | 主要代价 | 结论 |
| --- | --- | --- | --- |
| 为现有 `install.ps1` 加 CLI 包装 | 改动最少，复用下载逻辑 | 当前逐文件覆盖遇到失败会留下混合版本；还会检查 Node/npm、操作安装注册与快捷方式 | 不宜直接作为正式自更新 |
| 独立更新协调器，暂存完整发行包并带备份切换安装目录 | 保持公开安装路径，可独立测试更新流程，支持失败恢复 | 需要处理目录所有权、运行中实例、CMD 自覆盖和中断恢复 | 推荐 |
| 先把启动器也改为多版本目录与稳定 bootstrap | 后续切换版本更自然 | 会迁移现有入口、PATH、快捷方式和安装布局，超出本次功能需要 | 暂缓 |

推荐新增 `update-launcher.ps1`，通过内部 `-CheckOnly` 区分查询与执行。必要时把事务函数拆为小型共享脚本，供安装器后续复用；不在 `deepseek.cmd` 中实现下载、JSON、路径验证和恢复逻辑。

“带备份切换”表示可恢复的多个步骤，不意味着两个目录重命名天然构成一次原子操作。中断窗口必须用安装目录之外的事务记录和恢复入口处理。

## 3. 对外行为

### 3.1 版本判断

1. 从命令所在安装目录读取 `VERSION`，不依赖当前工作目录，也不从 PATH 中寻找另一个安装副本。
2. 查询 `RYun601/dsh-launcher` 的最新稳定 Release，要求非草稿、非预发布，且标签符合 `v<VERSION>`。
3. 对合法版本执行语义版本比较。目标等于本地时输出已是最新，目标低于本地时输出本地较新；两者都不下载、不写文件。
4. 本地版本缺失或非法时可显示诊断，但自动更新应拒绝继续，并提示使用正式安装包修复；不能猜测版本或自动降级。
5. 更新完成后的版本必须与所选择的标签一致。安装包内 `VERSION` 不符应在替换之前失败。

GitHub 的 latest 接口提供最新完整发行版，不能据此省略本地版本比较；API 返回中也提供发行资产的名称、大小和 `digest`。使用这些字段前必须校验类型和格式。[GitHub Releases API](https://docs.github.com/en/rest/releases/releases?apiVersion=latest#get-the-latest-release)

### 3.2 查询结果与退出码

| 结果 | 建议退出码 | 文件影响 |
| --- | --- | --- |
| 检查成功，包括发现新版本 | `0` | 无安装、PATH、快捷方式或运行时变更 |
| 更新成功、已经最新、本地版本更新 | `0` | 仅更新成功时变更启动器文件 |
| 参数错误、网络失败、包验证失败、安装边界拒绝、安装忙 | `1` | 提交前保留原安装；原因和下一步写入输出 |
| 更新失败且已恢复旧版本 | `1` | 明确显示旧版本已恢复；不能报更新成功 |
| 更新失败且自动恢复未完成 | `2` | 保留恢复副本和事务记录，输出准确位置与恢复方式 |

CMD 必须原样传播更新器退出码。第一版使用现有的单动作规则：例如 `--upgrade-launcher --upgrade`、`--update-launcher -b`、`--upgrade-launcher --full` 都应拒绝。

### 3.3 正在运行的 DSH

第一版选择“服务停止后更新”。当已有启动锁、runner、前台进程、DSH 升级或卸载事务时，拒绝替换文件，并给出先停止、再更新的命令。身份查询不确定时保留现状并报安装忙，不能当成已停止。

更新器自身不自动停止或重新启动 DSH，不调用 npm，不切换运行时指针，不打开浏览器。这样可以避免更新中的脚本被旧 runner 后续加载，以及更改仍在使用的生命周期实现。

只在入口检查一次服务状态还不够：第一版需要安装维护锁，并让会与目录替换冲突的启动、DSH 升级、安装与卸载流程参与协调。固定加锁顺序，取得维护锁后再次确认无运行实例；已有启动锁依然独立保护启动所有权。这个同步点是自更新的验收项，不能留到以后再补。

## 4. 安装位置与数据边界

- 默认更新 `$PSScriptRoot` 所指的当前安装副本，路径必须经过绝对路径、长路径和重解析点检查。
- 第一版仅自动更新受管安装：位于用户目录内、所有权标记有效且 `InstallPath` 精确匹配、不属于 `.dsh` 或 `dsh-launch` 数据树。
- 检查安装目录中的 `.git` 文件或目录，并检测是否处于上级 Git 工作树之内；发现源码工作树则拒绝覆盖。不能把“目录名叫 dsh-launcher”当作所有权依据。
- 手动解压目录、缺少所有权标记的旧安装、位于其他盘的便携副本给出明确迁移说明；第一版不自动接管。后续若支持接管，需要独立设计文件清单和用户文件保护。
- `%USERPROFILE%\.dsh` 及其子目录绝不读取凭据、写入、移动、复制或删除；不能把备份该目录当作自更新的前置步骤。
- `%USERPROFILE%\dsh-launch` 中的 DSH 运行时、日志和指针保留。更新事务与恢复文件放在独立、受验证的启动器维护目录中，不与 DSH 状态文件混用。
- 保留原 `InstallationId` 和最终安装路径。保持 PATH 注册与快捷方式目标不变；发现无关文件、未知目录或重解析点时在变更前拒绝自动更新并报告，不先移走再决定怎么处理。

现有安装器会给已有目录重新生成所有权标记，因此仅凭这个标记不能证明目录中所有文件都属于启动器。应组合检查现有受管文件清单与目录内容。不得递归删除仅因包含 `deepseek.cmd` 就被判定为安装目录的任意文件夹。

## 5. 下载与包验证

1. 使用固定仓库的 GitHub API，设置明确的 User-Agent、请求与下载超时。网络错误、限流和找不到 Release 分开提示，不无上限重试。
2. 选择唯一、状态正常、名称精确为 `dsh-launcher.zip` 的资产。下载到唯一事务目录；API 查询、下载、解压全过程都在清理保护内。
3. 第一版正式发布前确认 GitHub 为新资产提供 `sha256` digest；若需要兼容缺失 digest 的发行流程，可由发布工作流额外生成同名 SHA-256 校验资产。两种校验材料都不存在时拒绝自动安装，提示手动更新。
4. 对下载大小与 SHA-256 进行校验。摘要可以验证内容与所选发行资产一致，但与 ZIP 同源的摘要不等于独立作者签名，不应在文档中宣称具有签名保证。
5. 解压前验证 ZIP 条目：拒绝绝对路径、`..` 越界、盘符/流路径、大小写归一后重名、异常链接和明显超限的条目。解压后再次确认所有文件位于暂存目录内。
6. 支持当前发行包的 `dsh-launcher/` 顶层目录；如兼容平铺结构，必须明确只接受其中一种结构，不能从多个候选目录任取一个入口。
7. 将 `release-files.txt` 本身纳入未来发行包，使验证器能从同一个发行清单核对完整文件集合。当前清单没有把自身打包，实施时必须同步工作流和测试，不能假设已存在。
8. 校验必需文件、包内版本与标签；使用 Windows PowerShell 5.1 解析所有发布脚本，校验 `install.ps1` 无 BOM。验证完成前不 dot-source 包内 PowerShell。

资产字段的依据见 [GitHub Releases API 的响应结构](https://docs.github.com/en/rest/releases/releases?apiVersion=latest#get-the-latest-release)。签名与独立信任根可作为后续供应链增强，不是第一版引入证书管理的理由。

## 6. 文件切换和中断恢复

建议事务步骤如下，每一步写明状态、源版本、目标版本、路径和事务 ID：

1. **查询与暂存**：下载并验证候选包。失败仅清理本次创建的临时文件。
2. **维护锁与复检**：锁放在替换范围外；获取后重新检查安装版本、目录身份、服务状态及其他事务，防止下载期间发生变化。
3. **准备恢复执行器**：将完整的更新执行代码复制到替换范围之外，再由它执行切换。执行器不能在提交期间继续读取原安装目录中的函数。
4. **备份旧安装**：将原目录移至同卷、相邻且经过验证的备份位置。为旧目录清单、版本和所有权标记保留恢复记录。
5. **放置新安装**：把同卷暂存目录移至原安装路径，恢复受管安装身份。跨卷下载目录不能直接当作原子重命名来源。
6. **离线烟雾验证**：验证新入口帮助、版本输出和退出码；需要先解决审查中 `--version` 的路径与运行时来源问题。烟雾检查不启动 DSH、不访问 npm、不创建快捷方式。
7. **提交**：写入成功状态，报告版本变化，再清理本次旧安装备份。清理失败时提示并保留准确路径，不把安装成功改报失败。
8. **失败恢复**：移走失败候选，恢复原安装并验证入口。任何恢复失败都保留备份与事务记录，返回 `2`，禁止在 `finally` 中无条件删除唯一恢复副本。

重命名旧目录之后掉电，会出现原安装路径暂时缺失的窗口。事务目录应预先带有可直接运行的 `recover-launcher.ps1`，启动更新时输出其位置；安装器重试也应识别该事务并提供恢复。原命令入口不可用时，不能只提示再次运行 `deepseek`。

CMD 自覆盖需要单独证明：更新时调用的 `deepseek.cmd` 可能还在解释执行，简单 `call :update` 后回到被替换文件的下一行并不可靠。分派代码必须在覆盖前建立完整的返回/退出路径，例如经验证的预解析执行块加外置执行器；不在更新后继续依赖原批处理文件的行偏移。必须用明显增减行数的新旧 CMD 夹具验证最终退出码。

## 7. 实施文件与顺序

| 文件或模块 | 后续改动 |
| --- | --- |
| `deepseek.cmd` | 新动作白名单、互斥、帮助、同步返回退出码和自覆盖保护 |
| `update-launcher.ps1`（拟新增） | 查询、下载、验证、更新协调 |
| 维护锁与恢复执行器（按实现规模拆分） | 共享维护互斥、事务记录、恢复；保持 PS 5.1 兼容 |
| 启动、安装、DSH 升级和卸载入口 | 参与维护互斥，不复制启动状态机 |
| `release-files.txt`、`.github/workflows/release.yml` | 携带新文件及包内清单；必要时生成摘要资产；保持 ZIP 名与 Release 标题规则 |
| `tests/launcher-update-behavior.Tests.ps1`（拟新增） | 隔离验证自更新、失败恢复、并发和退出码 |
| `tests/startup-behavior.Tests.ps1`、`tests/release-package-behavior.Tests.ps1` | 分派、自覆盖、归档完整性和真实归档烟雾测试 |
| `README.md`、`README.en.md`、`AGENTS.md` | 同步命令、支持范围、数据边界及文件职责 |

实施顺序：先修复测试隔离与卸载恢复问题，再建立更新用包验证和事务测试；然后接入新命令及维护互斥，最后同步双语文档与发行流程。只有准备正式发布时才更新 `VERSION`。

## 8. 必须通过的验收场景

| 类别 | 场景与断言 |
| --- | --- |
| CLI | 两个新动作能正确分派；未知参数、冲突动作、无效修饰符报错；保留现有参数行为 |
| 版本 | 新版本、相同版本、本地较新、非法标签、本地缺失版本、包内版本不匹配；不静默降级 |
| 网络 | 超时、API 限流、404、下载中断、缺失资产、缺失/错误摘要；原安装逐字节保持 |
| 归档 | 缺文件、错误根结构、路径穿越、重名、非法条目、PS 5.1 不可解析脚本、安装器 BOM；提交前拒绝 |
| 安装边界 | 空格、中文、单引号、`!`、长路径/8.3、重解析点、Git 仓库、无主目录、`.dsh` 和运行数据路径 |
| 并发 | 两次更新只允许一次提交；更新与启动、DSH 升级、卸载相互排斥；身份不确定时不覆盖 |
| 生命周期 | 有前台/后台/STARTING 实例时拒绝；检查更新允许在服务运行时执行 |
| 失败恢复 | 旧目录搬移失败、新目录放置失败、烟雾失败、恢复失败、备份清理失败及关键步骤强制终止 |
| 自覆盖 | 新旧 `deepseek.cmd` 长度和布局不同，最终仍返回真实 `0`、`1`、`2`，不会掉入其他动作 |
| 数据保护 | 仅用合成 profile；`.dsh` 哨兵、运行时指针、日志、用户 PATH、快捷方式不被读写或移动 |
| 发行 | 新文件与包内清单一致；实际 ZIP 解压后命令可用；完整 Windows 套件在待发布同一 commit 验收 |

现有 `v0.1.11` 用户没有自更新入口。首次迁移仍需要安装包含新命令的版本；不能承诺旧版本执行新命令即可生效。新功能发布说明需中英双语，明确这一迁移步骤及受管安装限制。
